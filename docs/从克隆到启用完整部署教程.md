# 从克隆仓库到启用服务：完整部署教程

本文档面向第一次部署本项目的管理员。目标是在 Windows 的 WSL2 Ubuntu 24.04 中，从克隆仓库开始，完成前端构建、后端安装、Token 获取、Podman、全局 frpc、Minecraft 端口池、玩家资源包下载和 systemd 开机自启。

> 本文中的命令必须按标注在 **Windows PowerShell** 或 **WSL Ubuntu** 中执行，不要混用。

## 0. 开始前准备参数

执行前先向 frps/代理主机管理员取得以下信息：

| 参数 | 示例 | 说明 |
|---|---|---|
| 仓库地址 | `<REPOSITORY_URL>` | 当前本地仓库尚未配置 Git remote，文档不能替你猜测地址 |
| frps 公网地址 | `example.com` | 写入 `serverAddr`，不要带 `http://` |
| frps 控制端口 | `<FRPS_CONTROL_PORT>` | frps 的 `bindPort`，不是 Minecraft 游戏端口 |
| frps Token | `<FRP_TOKEN>` | frps 和 frpc 必须一致，写入受限的 `config/frpc.toml` |
| frpc 客户端名 | `mc-host-01` | 多台客户端时必须唯一 |
| Minecraft 远端端口池 | `30000-30099` | 玩家连接端口，须在 frps、防火墙和云安全组同时放行 |
| 资源包 FRP 上游端口 | `18080` | frps 主机内部供 HTTPS 反向代理访问的 HTTP 端口 |
| 资源包公网 HTTPS 地址 | `https://example.com:<HTTPS_PORT>` | 必须确实有 TLS 入口，不能把普通 TCP 映射误写成 HTTPS |
| PaperMC 联系方式 | `ops@example.com` | 用于 HTTP User-Agent，请换成真实运维联系地址 |

全文出现 `<...>` 的地方都必须替换为真实值。不要原样复制带尖括号的占位符。

## 1. 安装 WSL2 Ubuntu 24.04

### 1.1 Windows PowerShell（管理员）

```powershell
wsl --install -d Ubuntu-24.04
```

如果已经安装，查看准确的发行版名称：

```powershell
wsl.exe --list --verbose
```

首次打开 Ubuntu，按照提示创建 Linux 用户。

### 1.2 WSL Ubuntu：启用 systemd

```bash
sudo tee /etc/wsl.conf >/dev/null <<'EOF'
[boot]
systemd=true

[network]
generateResolvConf=true
EOF
```

回到 **Windows PowerShell**：

```powershell
wsl --shutdown
wsl -d Ubuntu-24.04
```

重新进入 WSL 后验证：

```bash
ps -p 1 -o comm=
```

必须输出：

```text
systemd
```

如果不是 `systemd`，不要继续安装服务，先检查 `/etc/wsl.conf` 并再次执行 `wsl --shutdown`。

## 2. 安装 Git 与 Node.js 26

以下命令均在 **WSL Ubuntu** 执行。

### 2.1 基础工具

```bash
sudo apt-get update
sudo apt-get install -y ca-certificates curl git
```

### 2.2 Node.js

项目固定使用 Node.js 26。通过 NodeSource 安装：

```bash
curl -fsSL https://deb.nodesource.com/setup_26.x -o /tmp/nodesource_setup.sh
sudo -E bash /tmp/nodesource_setup.sh
rm -f /tmp/nodesource_setup.sh
sudo apt-get install -y nodejs
```

验证版本：

```bash
node --version
npm --version
```

Node 应输出 `v26.x.x`，npm 应输出 `11.x.x`。版本不匹配时不要继续构建。

## 3. 克隆仓库

```bash
cd ~
git clone --branch main <REPOSITORY_URL> mc-minigame-manager
cd ~/mc-minigame-manager
```

确认目录正确：

```bash
test -f scripts/install-wsl.sh
test -f frontend/package-lock.json
```

两条命令都应无输出并返回成功。

> 当前开发工作副本没有配置远端地址，因此必须先由仓库维护者提供 `<REPOSITORY_URL>`；不要自行猜测 GitHub 地址。

初始化实际配置。此命令从 Git 中的示例创建 `config/`，生成随机管理 Token，并且不会覆盖
已经存在的配置：

```bash
bash scripts/init-config.sh
```

示例文件仍位于 `.env.example` 和 `deploy/frp/frpc.toml.example`；不要直接修改示例。
实际使用的是以下两个被 Git 忽略的文件，可以直接用 VS Code 编辑，无需 sudo：

```text
config/mc-manager.env
config/frpc.toml
```

## 4. 构建生产前端

安装脚本要求后端包中已经存在前端构建产物，所以必须先构建：

```bash
cd ~/mc-minigame-manager
bash scripts/build-frontend.sh
```

脚本会校验 Node.js 26 和 npm 11+。依赖锁文件以及 Node/npm 版本未变化时，它会跳过
`npm ci`；随后每次都执行测试、TypeScript 类型检查和 Vite 生产构建。

验证构建产物：

```bash
test -f src/mc_manager/static/index.html
```

若提示缺少该文件，不要运行安装脚本，先处理前端构建错误。

## 5. 执行系统安装

先执行安装，但不要立即启动服务。此时后端配置已有随机 Token；frpc 可以暂时保留示例
地址和示例 Token。随后按照第 6 节修改后端配置并重新同步，再启动 API 与 Worker；需要公网
连接时再按照第 9 节配置 frpc。

```bash
cd ~/mc-minigame-manager
sudo bash scripts/install-wsl.sh
```

脚本会自动完成：

1. 安装 Python 3.12 venv、Podman 和 rootless 容器依赖；
2. 下载并校验 frpc 0.68.0；
3. 将 frpc 安装到 `/usr/local/bin/frpc`；
4. 将项目安装到 `/opt/mc-manager`；
5. 创建 `/opt/mc-manager/.venv`；
6. 创建 API、Worker、frp 系统用户和目录权限；
7. 将项目 `config/` 中的实际配置以受限权限部署到 `/opt/mc-manager/config/`；
8. 旧安装首次升级时，把原 `/etc` 配置自动迁移回项目 `config/`，无需重新填写；
9. 在 `/etc` 创建指向部署副本的兼容符号链接；
10. 安装 systemd 单元，但不会替你填 frps 参数，也不会自动启用服务。

安装脚本可以安全重复执行，并会避免无意义的重复下载：

- 仅当系统包缺失时才执行 `apt-get update/install`；
- `/usr/local/bin/frpc` 已是指定版本时不会重新下载；
- `/opt/mc-manager/.venv` 会保留，不再每次删除重建；
- 项目源码和依赖未变化时会完全跳过 `pip install`；
- 项目发生变化时会重新安装本地 Python 包，只有新增或版本不满足的依赖才需要联网下载；
- 项目 `config/` 中的后端、frpc 配置和 Token 始终是唯一配置源。

验证 frpc：

```bash
/usr/local/bin/frpc --version
```

应输出 `0.68.0`。

## 6. 配置后端

直接用 VS Code 编辑项目文件：

```text
config/mc-manager.env
```

至少核对以下项目：

```dotenv
MC_DATABASE_URL=sqlite:////var/lib/mc-manager/mc-manager.db
MC_AUTO_CREATE_SCHEMA=false
MC_STORAGE_ROOT=/srv/mc-manager
MC_PORT_MIN=30000
MC_PORT_MAX=30099
MC_PUBLIC_GAME_HOST=example.com
MC_PUBLIC_GAME_PORT_MIN=30000
MC_BACKUP_LIMIT=10
MC_RUNTIME_BACKEND=podman
MC_PODMAN_BINARY=/usr/bin/podman
MC_API_TOKEN=<init-config.sh 生成的随机值，不要改回示例值>
MC_PAPERMC_USER_AGENT="mc-minigame-manager/0.2.0 (你的真实运维邮箱)"
MC_RESOURCE_PACK_BASE_URL=
MC_MAX_RESOURCE_PACK_BYTES=262144000
```

注意：

- `MC_PORT_MIN`、`MC_PORT_MAX` 必须与后面的 frpc 本地端口范围完全一致；
- `MC_PUBLIC_GAME_HOST` 是玩家连接的 frps 公网域名，`MC_PUBLIC_GAME_PORT_MIN` 是远端端口池首端口；前端按本地端口偏移计算并显示可复制地址；
- `scripts/init-config.sh` 已生成随机 `MC_API_TOKEN`，不要把它改成示例值；
- 生产 systemd 单元目前固定让 API 监听 `127.0.0.1:8080`，环境文件中的 API host/port 不会覆盖该启动参数；
- 数据默认放在 WSL ext4 的 `/srv/mc-manager`，不要改到 `/mnt/c`；
- 若暂时没有资源包公网地址，保持 `MC_RESOURCE_PACK_BASE_URL=` 为空即可，普通地图和游戏仍可使用，但上传“玩家资源包”会被拒绝；
- 资源包公网入口准备好以后再填写，例如 `https://example.com:<HTTPS_PORT>`，填写后需要重启 API，并重新导入带资源包的 Map。

若服务已经安装，修改项目配置后先重新部署，再重启：

```bash
sudo bash scripts/install-wsl.sh
sudo systemctl restart mc-manager-api.service mc-manager-worker.service
```

systemd 读取的是 `/opt/mc-manager/config/mc-manager.env`。该文件是安装脚本生成的受保护
部署副本，不要直接修改；否则下一次部署会被项目 `config/mc-manager.env` 覆盖。

## 9. 配置全局 frpc

### 9.1 编辑 frpc 配置和 Token

```text
config/frpc.toml
```

完整示例：

```toml
serverAddr = "example.com"
serverPort = <FRPS_CONTROL_PORT>
user = "mc-host-01"

auth.method = "token"
auth.token = "<FRP_TOKEN>"

transport.tls.enable = true

webServer.addr = "127.0.0.1"
webServer.port = 7400

# 第一个范围是 WSL 本地端口，必须等于 MC_PORT_MIN/MAX。
# 第二个范围是 frps 公网 Minecraft 端口，两个范围的端口数量必须相同。
{{- range $_, $v := parseNumberRangePair "30000-30099" "30000-30099" }}
[[proxies]]
name = "mc-{{ $v.First }}"
type = "tcp"
localIP = "127.0.0.1"
localPort = {{ $v.First }}
remotePort = {{ $v.Second }}

healthCheck.type = "tcp"
healthCheck.timeoutSeconds = 3
healthCheck.maxFailed = 3
healthCheck.intervalSeconds = 10
{{- end }}
```

必须替换：

- `serverAddr`：frps 公网域名或 IP，示例使用 `example.com`；
- `serverPort`：frps 控制端口，即服务端 `bindPort`；
- `user`：此 WSL 主机的唯一名称；
- `auth.token`：与 frps 一致的认证 Token，保留双引号；
- 两个端口范围：本地池与远端池；
- `config/mc-manager.env` 中的 `MC_PORT_MIN/MAX` 必须等于第一个范围。
- `MC_PUBLIC_GAME_HOST` 必须是 `serverAddr` 对外可访问的主机，`MC_PUBLIC_GAME_PORT_MIN` 必须等于第二个范围的首端口。

`config/frpc.toml` 包含 Token，初始化脚本会将其权限设为 `0600`，且整个实际配置被 Git
忽略。安装后部署副本为 `/opt/mc-manager/config/frpc.toml`，权限是 `root:frp 0640`。

frps 主机还必须同时完成：

1. `allowPorts` 允许全部远端游戏端口；
2. 操作系统防火墙允许这些 TCP 端口；
3. 云服务器安全组允许这些 TCP 端口；
4. 没有其他 frpc 客户端占用相同 `remotePort`。

### 9.2 校验配置

```bash
sudo bash scripts/install-wsl.sh
sudo -u frp /usr/local/bin/frpc verify -c /opt/mc-manager/config/frpc.toml
```

必须看到验证成功后再启动。若失败，先修复配置，不要跳过 `verify`。

### 9.3 启动 frpc

```bash
sudo systemctl start frpc.service
systemctl --no-pager --full status frpc.service
```

查看日志：

```bash
sudo journalctl -u frpc.service -n 100 --no-pager
```

出现登录 frps 成功和代理启动成功后，Minecraft 端口池才算生效。

玩家连接地址为：

```text
example.com:<Game 启动后分配的远端端口>
```

## 10. 配置玩家资源包公网下载

Paper 不会直接读取服务器本地 ZIP 并传输给客户端。系统会：

1. 将资源包保存在本机 Map 中；
2. 计算 SHA-1 和 SHA-256；
3. 在 `server.properties` 写入公开 URL；
4. 由 Paper 在玩家进服时通知客户端下载；
5. 由 FastAPI 的匿名 `/resource-packs/` 路由实际提供 ZIP。

### 10.1 在 frpc 中增加 HTTP 上游

在项目 `config/frpc.toml` 末尾追加：

```toml
[[proxies]]
name = "mc-resource-packs"
type = "tcp"
localIP = "127.0.0.1"
localPort = 8080
remotePort = 18080
```

这里的 `18080` 是示例，可以替换，但必须由 frps 允许且不能与其他代理冲突。

重新验证并重启：

```bash
sudo bash scripts/install-wsl.sh
sudo -u frp /usr/local/bin/frpc verify -c /opt/mc-manager/config/frpc.toml
sudo systemctl restart frpc.service
systemctl --no-pager --full status frpc.service
```

### 10.2 正确理解 HTTP 与 HTTPS

上述 TCP 代理把：

```text
frps:18080 → frpc → WSL 127.0.0.1:8080
```

它提供的是普通 HTTP，不会自动产生 HTTPS。因此：

- 如果直接让玩家访问该端口，地址只能写成 `http://example.com:18080`；
- 只有当 `example.com:<HTTPS_PORT>` 上确实有 Nginx、Caddy、面板反代或代理服务终止 TLS 时，才能填写 `https://example.com:<HTTPS_PORT>`；
- `transport.tls.enable=true` 只保护 frpc 与 frps 之间的隧道，不等于玩家下载 URL 已经是 HTTPS。

直接公开 `18080` 会暴露整个 FastAPI 入口，而不仅是资源包路径。管理 API 仍要求 Token，但不建议通过明文 HTTP 远程管理。

### 10.3 推荐的 HTTPS 拓扑

推荐在代理主机上：

1. frps 接收 `18080`，通过防火墙限制为仅本机反向代理可访问；
2. 公网 HTTPS 服务监听 `<HTTPS_PORT>`；
3. 只把 `/resource-packs/` 转发到 `http://127.0.0.1:18080`；
4. 其他路径直接返回 404；
5. 使用浏览器和 Minecraft 客户端都信任的 TLS 证书。

Nginx 示例（在代理主机执行，不是在 WSL 执行）：

```nginx
server {
    listen <HTTPS_PORT> ssl;
    server_name example.com;

    # 管理前端使用 8 MiB 分片；16 MiB 足以容纳单片和协议开销。
    client_max_body_size 16m;

    ssl_certificate /path/to/fullchain.pem;
    ssl_certificate_key /path/to/private-key.pem;

    location /resource-packs/ {
        proxy_pass http://127.0.0.1:18080;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-Proto https;
    }

    # 如果同一 HTTPS 域名还提供管理前端和地图上传，需要转发其余路径。
    # 完成请求会等待解压和校验，因此仍需预留足够读取时间。
    location / {
      proxy_pass http://127.0.0.1:18080;
      proxy_set_header Host $host;
      proxy_set_header X-Forwarded-Proto https;
      proxy_request_buffering off;
      proxy_read_timeout 3600s;
      proxy_send_timeout 3600s;
    }
}
```

如果代理主机已有面板或 HTTPS 反代，只需实现同样的路径转发，不必使用这份 Nginx 示例。

### 10.4 写入后端配置

公网 HTTPS 入口确认可用后：

```text
config/mc-manager.env
```

填写：

```dotenv
MC_RESOURCE_PACK_BASE_URL=https://example.com:<HTTPS_PORT>
```

然后重启 API：

```bash
sudo bash scripts/install-wsl.sh
sudo systemctl restart mc-manager-api.service
curl --fail http://127.0.0.1:8080/healthz
```

资源包 URL 在导入 Map 时固化。修改该环境变量后，旧 Map 不会自动改 URL；必须重新导入带资源包的 Map。

上传成功后，在管理台 Map 详情页点击“测试下载”，并从玩家所在网络访问该 URL。下载响应应包含：

- HTTP 200；
- `Content-Type: application/zip`；
- `ETag`；
- `Cache-Control: public, max-age=31536000, immutable`。

资源包下载路由故意不要求管理 Token，因为 Minecraft 客户端无法发送管理 Token。资源包中不得存放任何密钥或私有文件。

## 11. 启用开机自启

### 11.1 frpc 已配置完成

```bash
sudo systemctl enable --now mc-manager.target
```

该 target 会拉起：

- `mc-manager-api.service`；
- `mc-manager-worker.service`；
- `frpc.service`。

`mc-manager.target` 使用 `Wants=`，所以 target 显示 active 不代表所有子服务都成功。必须逐项检查：

```bash
systemctl is-active mc-manager-api.service
systemctl is-active mc-manager-worker.service
systemctl is-active frpc.service
curl --fail http://127.0.0.1:8080/healthz
```

前三项应输出 `active`，健康检查应成功。

### 11.2 暂时没有 frps

只启用本机管理功能：

```bash
sudo systemctl enable --now mc-manager-api.service mc-manager-worker.service
```

此时可以在本机上传地图、创建 Game 和测试后端，但公网玩家无法连接。拿到 frps 参数后完成第 9、10 节，再执行：

```bash
sudo systemctl enable --now frpc.service mc-manager.target
```

## 12. Windows 冷启动 WSL

WSL 发行版通常需要被 Windows 唤醒，里面的 systemd 服务才会运行。

先在 **Windows PowerShell** 查询名称：

```powershell
wsl.exe --list --verbose
```

编辑项目中的 `deploy/windows/start-wsl.ps1`，把：

```powershell
$Distribution = "Ubuntu"
```

改为实际名称，例如：

```powershell
$Distribution = "Ubuntu-24.04"
```

在 Windows 任务计划程序创建任务：

1. 触发器：计算机启动时；
2. 用户：注册该 WSL 发行版的 Windows 用户；
3. 选择“无论用户是否登录都运行”；
4. 程序：`powershell.exe`；
5. 参数：`-NoProfile -ExecutionPolicy Bypass -File "脚本的Windows绝对路径"`。

重启 Windows 后再次逐项检查 API、Worker 和 frpc，不要只检查 target。

## 13. 第一次使用

1. 打开 `http://127.0.0.1:8080/`；
2. 输入 `MC_API_TOKEN` 等号右侧内容；
3. 进入“地图”，上传包含 `level.dat` 的 `map.zip`；
4. 如果需要客户端材质，单独上传一个根目录包含 `pack.mcmeta` 的玩家资源包 ZIP；
5. 地图名称自动取自 ZIP 文件名；系统直接从 `level.dat` 读取 Minecraft 版本并选择 Paper build 和 Java 主版本；
6. 从 Map 创建 Game；
7. 启动 Game，推荐让系统自动分配端口；
8. 等待任务成功；
9. 玩家连接 `example.com:<分配端口>`；
10. 停服时使用管理台“停止”，让 Paper 优雅退出并创建备份，不要直接杀容器。

第一次启动某个版本时，Worker 可能需要下载 Paper JAR 和拉取对应 Java 容器镜像，耗时会比后续启动长。WSL 必须能访问 PaperMC 和配置的容器镜像源。

## 15. 常见故障

### 15.1 安装脚本提示缺少前端构建产物

```bash
cd ~/mc-minigame-manager
bash scripts/build-frontend.sh
sudo bash scripts/install-wsl.sh
```

### 15.2 frpc 可执行文件找不到

正确路径：

```text
/usr/local/bin/frpc
```

检查：

```bash
ls -l /usr/local/bin/frpc
/usr/local/bin/frpc --version
```

### 15.3 frpc 提示 Token 缺失或鉴权失败

```bash
grep '^auth.token =' config/frpc.toml | sed 's/=.*/= "***"/'
sudo bash scripts/install-wsl.sh
sudo -u frp /usr/local/bin/frpc verify -c /opt/mc-manager/config/frpc.toml
```

确认 `auth.token` 已填写、仍带双引号且与 frps 一致。不要把真实 Token 输出到聊天或日志。

### 15.4 frpc verify 失败

```bash
sudo -u frp /usr/local/bin/frpc verify -c /opt/mc-manager/config/frpc.toml
sudo journalctl -u frpc.service -n 100 --no-pager
```

重点检查：

- `serverAddr` 是否只写域名/IP；
- `serverPort` 是否是 frps 控制端口；
- Token 是否与 frps 一致；
- TOML 字符串是否有引号；
- 端口是否为整数且没有保留 `<...>` 占位符。

### 15.5 target active，但 API/Worker/frpc 有一个失败

这是 `Wants=` 的正常行为。逐项检查：

```bash
systemctl --no-pager --full status \
  mc-manager-api.service \
  mc-manager-worker.service \
  frpc.service
```

### 15.6 API 启动失败

```bash
sudo journalctl -u mc-manager-migrate.service -n 100 --no-pager
sudo journalctl -u mc-manager-api.service -n 100 --no-pager
```

### 15.7 Worker 或 Paper 启动失败

```bash
sudo journalctl -u mc-manager-worker.service -n 200 --no-pager
```

核对 Java 主版本、Paper build、镜像网络和磁盘空间。

### 15.8 玩家不能连接

确认：

1. 管理台中的 Game 已进入运行状态；
2. 玩家使用的是 Game 分配的远端端口；
3. frpc 为 active；
4. frps 允许该端口；
5. 服务器防火墙和云安全组允许该 TCP 端口；
6. 该 remote port 没有被其他客户端占用。

### 15.9 玩家资源包下载失败

确认：

1. `MC_RESOURCE_PACK_BASE_URL` 是玩家可访问地址，不是 `127.0.0.1`；
2. 如果填写 `https://`，对应端口确实终止 TLS；
3. HTTPS 反向代理只转发 `/resource-packs/` 到 FRP HTTP 上游；
4. 资源包 ZIP 根目录直接包含有效 `pack.mcmeta`；
5. 修改公网地址后已重启 API并重新导入 Map；
6. Map 详情中的“测试下载”从玩家网络可以打开。

## 16. 升级项目

在 WSL 中：

```bash
cd ~/mc-minigame-manager
git pull --ff-only
bash scripts/build-frontend.sh
sudo bash scripts/install-wsl.sh
sudo systemctl restart mc-manager-api.service mc-manager-worker.service
sudo -u frp /usr/local/bin/frpc verify -c /opt/mc-manager/config/frpc.toml
sudo systemctl restart frpc.service
```

安装脚本会保留项目 `config/` 和现有生产 venv，并重新同步受保护的生产配置副本。它根据源码指纹决定是否重装本地 Python 包；系统依赖和 frpc 版本已满足时不会重复联网下载。升级后仍应重新执行第 14 节验收。

如果这是从仍使用 `/etc/mc-manager`、`/etc/frp` 的旧版本首次升级，而且项目 `config/`
尚不存在，请不要先执行 `scripts/init-config.sh`；先运行 `scripts/build-frontend.sh`，再运行
新版安装脚本。它会先迁移旧配置和 Token，再建立兼容符号链接。
